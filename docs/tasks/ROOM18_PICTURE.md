# Задание: комната 18 (колдун) целиком картинкой в стиле CPC

## Контекст
Проект — порт Bruce Lee (ZX Spectrum) на Вектор-06Ц: `~/projects/brucelee-v06c` (git, ветка main, без remote).
Логика и столкновения — ZX (точный перевод Z80 → i8080, `src/i8080`). Платформа Вектора — `src/vec`: вывод, звук,
заставка. Персонажи, палитры и звук взяты из CPC-версии. Хроника решений — `docs/JOURNAL.md`, раскладка памяти —
`docs/VEC_LAYOUT.md`. Отвечать и комментировать по-русски.

Владелец хочет, чтобы комната 18 (зал колдуна, номер комнаты `zv_FE03 = 18`) выглядела как его рисунок
`orig/room18_art.png`. Это 256×180, раскладка ZX, вид CPC: малиновый зал, крупный красный колдун в синем.
Раскладка рисунка совпадает с ZX: площадка, пол, колонны и нижний зал на тех же местах. Это проверено наложением.

## Почему не получилось тайлами (не повторять)
- Комнаты рисуются тайлами 8×8 из общего набора на все комнаты (9800, 256 узоров, 2 КБ). В клетке два цвета:
  атрибут из таблицы 6300, номера палитры комнаты, `src/vec/roompal.asm`.
- Логика ZX определяет класс клетки по номеру тайла в карте 6040..62FF: `>= 40h` твёрдая, `18..1Fh` пол,
  остальные проходимые (`src/i8080/pers.asm`: `floor_below`, `obst_*`, `ceiling_above`).
- Верх рисунка — около 300 разных клеток, а свободных номеров около 100. Попытка `tools/mkroom18.py` и её итог
  `build/room18_attempt*.png` — плохо.

## Что сделать
Выводить комнату 18 **картинкой поверх**: после обычного вывода тайлов (`plat_room`, `src/vec/render.asm`) при
`zv_FE03 = 18` распаковывать готовую картинку игрового поля (строки ZX 2..23 = 176 строк, три плоскости
A000/C000/E000) прямо на экран.

Логика, карта и классы клеток не меняются. Меняется только вид.

1. **Подготовка картинки** — `tools/mkroom18pic.py`, новый:
   - вход `orig/room18_art.png`, масштаб к 256×176;
   - палитра комнаты 18 — 8 номеров. Номера 1 (чёрный), 4 (зелёный), 6 (жёлтый) общие, их используют персонажи
     и шапка. Номера 0, 2, 3, 5, 7 свои: подобрать под рисунок и прописать в строке 18 `roompal.asm`;
   - выход — три плоскости по столбцам, как на экране Вектора: байт = 8 точек, столбец = 176 байт сверху вниз.
     Сжатие ZX0 **classic**: `tools/zx0/zx0 -f -c`. Распаковщик `dzx0` уже есть в игре (HL — поток,
     BC — приёмник).
   - дать владельцу превью PNG на согласование **до** встраивания.
2. **Память.** Свободно около 260 байт внизу (до `want`, см. `build/vec/brucelee.sym`) и около 85 в дырах
   (`HOLES=1 python3 -I tools/mkvecdata.py`). Нужно 3–5 КБ под сжатую картинку. Найти место — главная часть
   задачи. Варианты:
   - хранить часть блоков кадров спрайтов (`Z_SPRC` и дыры комнат, `tools/mkvecdata.py`) сжатыми;
   - сжать другие редко нужные данные.

   Сначала **оценка с цифрами** (откуда, сколько, цена по скорости), затем согласовать с владельцем. Решения по
   спрайтам владелец согласует сам («насчёт спрайтов не принимай решение — согласуй»).
3. **Вывод.** Распаковка в экран идёт через буфер или по столбцам, это решать вам. Учесть:
   - ZX-колдун анимирован: огненный шар летит по диагонали тайлом 0, фон за ним `tile_redraw` берёт из копии карты
     5D00 и перерисовывает клетку тайлом. На картинке это затрёт рисунок клетки. Нужно восстанавливать клетку из
     картинки, а не из тайла (`plat_tile` в `render.asm`, `tile_redraw`/`tile_put` в `room.asm`).
   - Перерисовка клеток вокруг персонажей (`repaint`, `render_q*.asm`) тоже берёт фон из тайлов. Для комнаты 18 фон
     должен браться из картинки, иначе за персонажами останутся тайлы ZX. Это самое сложное место: разобраться в
     `repaint`/`strip_build`/`dc_setup`.
   - Предмет в комнате 18 (тайл 14, ряд 19, столбец 29) — **оружие** (`r_D98D` «подбор оружия»), его нужно
     собрать. С 06.11 он нарисован мечом: `tile_fix` в комнате 18 подставляет узор меча в тайл 14, в остальных
     комнатах — фонарик. Предмет должен остаться видимым мечом и собираемым.
   - `run80 --ship` выключает `tile_fix` (RET) — вид не сверяется с ZX, логика сверяется полностью.
4. **Без регресса темпа** в остальных комнатах.

## Проверки (обязательно, `./build.sh check` — всё зелёное)
- Python 3 с Pillow.
- `run80` — логика и образ на 10 эталонах, расхождений 0. Карту и логику не трогать.
- `vecroomcheck` — 20 комнат. Он сравнивает экран с тайлами ZX, поэтому для комнаты 18 его придётся научить
  сравнивать с картинкой.
- `vecscreens` — титры, игра по шагам, звук, GAME OVER, темп. Эталон `tests/screens.json`, обновлять только
  намеренно (`--update`).
- `vecwater`, `vecsplash`.
- Темп: `node tools/vectempo.js 9000` — доля двухкадровых шагов около 17%, не хуже.
- Новый стенд: комната 18 телепортом, как в `tools/vecroomcheck.js` (`zv_FE0E`, `next_player`). Брюс ходит по залу,
  шар колдуна летит, и после каждого шага экран там, где нет персонажей, совпадает с картинкой.
  Негативный контроль: испорченная картинка ловится.

## Правила
- Эмуляторы — без окна и звука. Emu80 с окном — только по просьбе владельца (`tools/emu80_run.sh`).

- Вопросы владельцу — одним исчерпывающим раундом, с вариантами ответа.
