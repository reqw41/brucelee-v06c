# Логика под i8080 нативно (решение владельца 04.11.2026, вариант «б»)

Цель: логика ложится на i8080 сама по себе, а не повторяет устройство кода Z80. Поведение — то же:
каждая правка сверяется с эталонами ZX шаг в шаг (`tools/run80.js` — логика, `--ship` — боевой образ),
негативный контроль на каждый шаг.

## Исходное (замер `run80 --prof`, s7_visit, без ожидания кадра)
Логика ≈ 7 тыс. тактов на проход, код 6,1 КБ. Дороже всего:

| что | тактов/проход | откуда |
|---|---|---|
| pers_step (быстрый путь + вход/выход) | 2,3 тыс. | копия записи в pw и обратно циклом (22 байта) |
| pw_load в pass | 1,3 тыс. | запись Брюса копируется в pw только чтобы прочесть размер и положение |
| pers_fell, size, objects, step_body | 0,4–0,7 тыс. каждое | |

## Что меняется
1. **Без лишних копий записи.** pass читает Брюса прямо из его записи (размер — по описателю записи).
   Копия pw — только для шагающего персонажа, развёрнутая (`LD A,(HL) / LD (pw+k),A / INC HL`).
2. **Раскладка данных — под i8080, а не под ZX.** Поля, которые читаются вместе, — рядом; переменные FExx,
   часто нужные вместе (ввод, счётчики), — одним блоком, чтобы читать `LD HL,(nn)` по два. Раскладка задаётся
   EQU в tools/mkvecdata.py (адрес ZX -> адрес Вектора), сверка ходит по той же карте — эталоны не меняются.
3. **Ветвления — таблицами**, где ZX делает цепочки сравнений (выбор обработчика, направления, позы).
4. **JS-модель.** Где меняется ход вычислений (а не только адреса и развёртка), сначала правится
   src/model (сверка `tools/model_run.js` с эталонами), потом i8080 переписывается с неё один к одному.
